# 이슈 #1 토큰 분석과 실행 제한 변경

분석 대상은 `.loop-runtime/run-1791256048789-issue-1/`의 maker/checker JSONL입니다. 실제 AI 작업은 이 분석 과정에서 새로 실행하지 않았습니다.

## 281,048의 구성

| 구분 | maker | checker | 합계 |
|---|---:|---:|---:|
| 입력 토큰 | 134,500 | 143,708 | 278,208 |
| 그중 캐시 입력 | 102,784 | 116,736 | 219,520 |
| 캐시를 제외한 입력 | 31,716 | 26,972 | 58,688 |
| 출력 토큰 | 1,372 | 1,468 | 2,840 |
| runner의 입력+출력 합산 | 135,872 | 145,176 | 281,048 |

캐시 입력은 입력의 부분집합입니다. 219,520을 다시 더한 이중 집계는 아닙니다. 전체 합산의 약 78.1%가 캐시 입력입니다. 281,048은 코드 출력 길이도, 현재 문맥 창 크기도, 유료 신규 토큰만의 수치도 아닙니다. 세션 동안 누적된 입력과 출력을 합산한 값이며 실제 결제금액은 조회하지 않았습니다.

## 커진 원인

1. maker와 checker 두 세션의 사용량을 합산했습니다.
2. runner가 규칙·skills를 프롬프트에 넣었는데 에이전트가 같은 파일들을 다시 cat했습니다.
3. maker는 runner 문서·코드·state·ledger·run log도 읽었습니다. 관측된 명령 출력 중 일부는 7,104·11,040·6,533 문자였습니다. 이 과정을 반복하며 문맥이 커졌습니다.
4. 도구 실행 후에도 기존 문맥이 누적 입력 집계에 포함됐고 캐시 비중이 높았습니다.
5. 기능 테스트는 통과했지만 checker의 검증 단계가 잘못되어 실패 처리됐습니다. PR 생성 전 원격 CI를 요구한 계약은 수정했습니다.
6. 그 사용량을 패턴 추정치 23,050과 비교하는 제한을 적용해 재시도가 막혔습니다. 이 추정치와 실제 코딩 에이전트 세션의 합산 범위가 이 실험에 적합하지 않았습니다.

로그만으로 모델 내부 요청 각각의 입력 크기나 금액을 분해할 수는 없습니다. 위 캐시·입력·출력 값은 실제 usage이고, 문맥 재전송에 대한 설명은 도구 기록과 누적 지표를 바탕으로 한 해석입니다.

## 현재 제한

사용자 요청에 따라 토큰은 기록만 하고 다음 제한을 적용합니다.

- 이슈별 구현→독립 검증 사이클 최대 3회.
- 한 사이클에는 maker 1세션과 checker 1세션.
- 에이전트별 도구 작업 최대 20회. 21번째 작업 이벤트가 감지되면 프로세스를 종료합니다.
- 에이전트별 최대 10분, 일일 사이클 최대 288회.
- 공식 loop-context는 max-iterations·반복 실패 검사에 계속 사용하며 token-budget/budget-from-pattern 옵션은 전달하지 않습니다.
- 기존 실패 기록과 시도 횟수는 삭제하지 않습니다.

Codex 로그의 turn.started는 maker에 1개, checker에 1개였습니다. 이 이벤트만 제한하면 내부의 여러 도구 실행을 제어할 수 없습니다. 따라서 여기서 “턴 제한”은 구현·검증 사이클 제한으로 정의하고 도구 작업·시간도 함께 제한합니다. started/completed가 같은 작업 ID이면 한 번만 집계합니다.

프롬프트에는 runner 문서·전체 run log를 다시 읽지 말도록 명시해 불필요한 문맥 확대도 줄였습니다.

## 원격 CI와 CLI

원격 CI는 허용되어 있습니다. 프로그램은 로컬 checker 승인 → commit/push → PR 생성 → GitHub Actions의 정확한 SHA 검사 순서로 진행합니다. 실제 PR #4에서 같은 SHA의 push/PR CI가 모두 성공했습니다.

CLI는 명령줄 프로그램입니다. Codex CLI는 실제 구현·검증에, gh CLI는 GitHub 조회·PR 생성에 사용하고 있습니다. AI에게 직접 gh 쓰기·merge를 맡기지 않고 coordinator가 실행하도록 역할을 나눈 것이지 CLI 전체를 금지한 것이 아닙니다. PR 머지와 이슈 종료는 사용자 요청에 따라 계속 금지합니다.
